# README 与发布帖的写法（自查清单）

这份清单是给本仓库的 README 和 DSH 讨论区的「Show Your Plugins!」帖用的。结论来自对
`deepseek-ai/deepseek-harness` 讨论区同类帖子的观察（`Show Your Plugins!` 分类约 1862 条，
按 upvote/评论排序的头部帖子）以及同类竞品 README 的结构对比，不是凭空发挥。

## 一、第一屏（读者 5 秒内要能回答三个问题）

- [ ] 第一段是**场景 + 结果**，不是定义。例：先说「agent 只能在你旁边等你输完密码」，
      再说「现在它和你共用同一个终端」。
- [ ] 第二段一句话讲清「是什么、给谁、凭什么不同」，加粗一句就够。
- [ ] 出现**安装命令**（可复制），最多三步。
- [ ] 出现一张**演示图/GIF**，图下面一句话说明「图上发生了什么、为什么这算亮点」。
- [ ] 首屏不出现实现细节（OSC、ControlMaster、文件路径）——这些放后面。

## 二、标题

- 公式：`DSH | 插件名 | 具体好处 / 去掉的麻烦 / 使用场景`。
- 抽象词（人机协同、统一日志）放副标题或正文第一句，不要放标题前半段。
- 双语标题可以，但中英各写一遍完整的好处，不要各半句。

## 三、结构

- [ ] 有目录（长文）；小标题 3–5 个，每段一个观点。
- [ ] 有一节「它不是什么」：降低误解，比多写十条功能更能建立信任。
- [ ] 有一张「能力一览」表，每行是**动作 + 结果 + 数字**（工具数、上限、测试数、依赖数）。
- [ ] 限制与安全模型放在中段靠前，而不是文末。
- [ ] 有 CTA：想让读者做什么（提 Issue、star、在讨论区讲自己的用法）。

## 四、可信度

- [ ] 非官方声明、许可证、CI/测试数、发布来源（npm provenance）。
- [ ] 不点名对比竞品；用「你可能想要的 / 本插件的答案」表格表达差异。
- [ ] 已知限制写清楚（平台、通道、一次性终端等），不藏。

## 五、写完后的验证

- [ ] **5 秒测试**：把第一屏给一个不看代码的人，问「这插件干什么、你什么时候会装」；
      答不上就重写第一屏。
- [ ] **扫读测试**：只看标题、加粗、表格、图注，能否复述卖点。
- [ ] **链接检查**：目录锚点、市场索引、release 链接都能打开。
- [ ] 7 天后看讨论帖评论/upvote 与 star 变化，作为下一轮调整依据。

1. 右侧栏「SSH 远程」→ 选主机 → 终端打开，出现 `ssh` 密码提示（2 秒）。
2. 人工输入密码、进入远端 shell（2 秒）。
3. agent 在同一个窗口里执行 `date && uname -a`，输出出现在窗口（3 秒）。
4. 人接着敲 `cd /tmp && pwd`，再让 agent 跑 `pwd`，显示状态保留（3 秒）。
5. 收尾定格在「同一块屏幕 + 同一条日志」（2 秒）。

字幕一句话：「同一个终端，两个操作者」。录制时把主机名/路径打码或换成 `web-01`。
