# P1 / P2 开发计划

来源：`research/ssh-competitors/report.md` 的竞品分析（2026-11-17）。
约束：本插件不改 DSH 源码；客户端 bundle 只能通过 `ctx.webTerminals` / `ctx.configForms`
拿数据，**没有 client → host 的查询通道**。这条约束决定了下面哪些能做在界面上。

## 已确认的技术前提

| 前提 | 结论 | 影响 |
| --- | --- | --- |
| 客户端可用的宿主服务 | `webTerminals`、`configForms`，无自定义 RPC | 隧道面板、文件抽屉、审计时间线这类「界面读宿主数据」的功能，必须先解决通道 |
| 终端渲染 | DSH 原生 xterm tab | 不能在终端内部加状态条/分屏；能加的只有侧栏面板与设置页 |
| 转发实现 | `ssh -N -L`，复用 ControlMaster，只绑回环 | 扩 `-D`/`-R` 只需改宿主的转发规格与取消标记 |
| 审计 | `audit/audit.jsonl`，宿主可读可导出 | 做「回放」的瓶颈在界面展示，不在数据 |

| 项 | 状态 | 说明 |
| --- | --- | --- |

| P1-2 危险命令分级 | **完成** | destructive / irreversible / session 三级 + 中文原因，审计带 `risk` |

| P1-5 断线提示与一键恢复 | **部分** | 工具在 socket 消失时会明确报 `CONSOLE_NOT_CONNECTED`；自动重连需要 DSH 终端生命周期钩子，暂不做 |

## 通道结论（2026-11-17，已解决）

两条路都试过了：

1. **Typert Remote（`ctx.remote` + `dsh-api-gateway`）不可用**：它要求构建期生成
   `InvocationDescriptor`，手写 bundle 接不上；SRC 模式只是未生成定义时的开发回退，不承诺稳定。
2. **`ctx.webServer` 具名路由可用**（采用）：宿主注册 `GET /plugins/dsh-remote-console/state.json`，
   面板同源 `fetch`。这是 DSH 插件本来就支持的能力，不需要构建链。

安全边界：只回计数与隧道方向（不回命令原文、不回屏幕内容），`no-store`，浏览器带 `Origin` 时
必须与 `Host` 同源；没有 webServer 的部署（headless/TUI）安静跳过，面板照常工作。

后续 P1-3 文件抽屉、P1-4 会话视图、P2-1 审计回放界面都可以走这条通道，每次只加一个路由字段与
对应的面板区块。

## P1：连接之后（按可交付性排序）

### P1-1 转发能力补齐（`-D` 已完成，`-R` 待做）

- **已完成**：`remote_forward` 支持 `kind: 'D'`（本地 SOCKS5），规格抽成 `forwardSpec()` 并加单测。
- **待做**：`kind: 'R'`（远端端口转到本地）。难点是就绪判定：`-L`/`-D` 看本地端口是否监听，
  `-R` 要连远端问「端口开了没」，需要在远端跑一次探测命令（`ss -ltn` / `nc -z`），失败要有可读原因。
- 验收：单测覆盖规格与取消标记；集成测试用 `sshd-harness` 起真 sshd 走一遍 `-R`。

### P1-2 危险命令分级

- 现状：`dangerousMatches` / `terminatingMatches` 命中即审批，但用户看不到「为什么危险」。
- 做法：命中项分级（destructive / irreversible / remote-impact），审批文案带上等级与具体原因，
  审计记录 `risk` 字段；不新增拦截规则，只把已有判断说清楚。
- 验收：单测覆盖分级；审计记录字段断言；文案不出现「可能」这类模糊词。

### P1-3 文件抽屉（**阻塞**：需要 client ↔ host 数据通道）

- 目标：终端右侧可拖拽的 SFTP 浏览，复用现有 ControlMaster，不新建连接。
- 前置：先调研 DSH 是否提供插件自定义 API 路由（`ctx.webserver` / tool RPC）；
  没有就要设计一条受控通道（只在回环、带会话校验）。
- 验收：目录浏览、上传/下载、删除确认；断线时失败关闭。

### P1-4 多标签终端（**待重新定义价值**）

- DSH 本身已经支持多个终端 tab，侧栏每点一次主机就是新 tab；直接做「标签」会重复。
- 有价值的部分是**会话视图**：哪些主机有活着的终端、哪个 agent 正在用。
- 前置同 P1-3（需要宿主数据）。
- 验收：面板列出「本会话的终端」，点一条切过去；不新增终端实现。

### P1-5 断线提示与一键恢复

- 目标：ssh 掉线后明确告知，并提示重连；cwd 不保证保留，文案不能承诺。
- 依赖：需要捕获终端退出事件（宿主侧已有 session 生命周期，客户端能否订阅待验证）。

## P2：差异化（别人没有的）

### P2-1 审计回放

- 宿主侧已能读 `audit.jsonl`。先做 agent 可用的时间线工具（按会话/时间聚合命令、传输、转发、审批），
  界面回放等 P1-3 的通道。
- 验收：一条命令能拿到「这次会话做了什么」的结构化时间线；不泄露屏幕内容与手敲文本。

### P2-2 主机健康快照（只读）

- 复用已认证连接，按需采集 CPU/内存/磁盘/负载（不做常驻监控、不装 agent）。
- 输出结构化结果，供 agent 判断；界面展示等 P1-3。
- 验收：采集失败要有明确原因；不新增连接。

### P2-3 窄屏布局（客户端可独立做）

- 侧栏面板在 <420px 时收成单列：主机行变紧凑、底部提示折行、搜索框占满。
- 验收：390px 下无横向溢出、按钮可点、焦点顺序正确。

## 建议顺序

1. P2-3（纯客户端，风险最低，马上能做）
2. P1-2（纯宿主，提升安全性）
3. P1-1 的 `-R`（补全转发能力）
4. 通道调研 → P1-3 / P1-4 / P2-1 界面部分
5. P1-5、P2-2

每个 PR 只做一项，带单测；界面改动仍按 AGENTS.md 第 9 条留待真实会话截图 + 录屏验收。
